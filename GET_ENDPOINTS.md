# How to Get VITE_API_URL and VITE_WS_URL

The `VITE_API_URL` and `VITE_WS_URL` are environment variables that point to your deployed AWS API endpoints. These values are **automatically generated** when you deploy your AWS backend.

## Where These Values Come From

These URLs are **outputs from your AWS CloudFormation stack** after you deploy the backend. They are generated by your AWS infrastructure (API Gateway).

## How to Get Them

### Method 1: From Deployment Script Output (Easiest)

When you run the deployment script, it automatically displays these endpoints at the end:

```bash
# After running: ./scripts/deploy.sh (or deploy.ps1 on Windows)
```

**Output will look like:**
```
=================================
✅ Deployment Complete!
=================================

API Endpoint:
  https://abc123xyz.execute-api.us-east-1.amazonaws.com/Prod

WebSocket Endpoint:
  wss://xyz789abc.execute-api.us-east-1.amazonaws.com/Prod
```

**Copy these values** - these are what you need!

### Method 2: From AWS CloudFormation Console

1. Go to [AWS CloudFormation Console](https://console.aws.amazon.com/cloudformation/)
2. Select your stack (usually named `finguard-stack`)
3. Click on the **Outputs** tab
4. Find these outputs:
   - **ApiEndpoint** → This is your `VITE_API_URL`
   - **WebSocketEndpoint** → This is your `VITE_WS_URL`

### Method 3: Via AWS CLI

Run these commands to get the endpoints:

```bash
# Get REST API endpoint
aws cloudformation describe-stacks \
    --stack-name finguard-stack \
    --query "Stacks[0].Outputs[?OutputKey=='ApiEndpoint'].OutputValue" \
    --output text

# Get WebSocket endpoint
aws cloudformation describe-stacks \
    --stack-name finguard-stack \
    --query "Stacks[0].Outputs[?OutputKey=='WebSocketEndpoint'].OutputValue" \
    --output text
```

## Format of These Values

### VITE_API_URL
- **Format**: `https://xxxxx.execute-api.us-east-1.amazonaws.com/Prod`
- **Example**: `https://abc123xyz.execute-api.us-east-1.amazonaws.com/Prod`
- **Purpose**: REST API endpoint for HTTP requests (GET, POST, etc.)

### VITE_WS_URL
- **Format**: `wss://xxxxx.execute-api.us-east-1.amazonaws.com/Prod`
- **Example**: `wss://xyz789abc.execute-api.us-east-1.amazonaws.com/Prod`
- **Purpose**: WebSocket endpoint for real-time connections

**Note**: WebSocket URLs **must** start with `wss://` (secure WebSocket), not `ws://`

## How to Use Them

### For Vercel Deployment

1. Go to your Vercel project dashboard
2. Navigate to **Settings** → **Environment Variables**
3. Add these variables:

   | Name | Value |
   |------|-------|
   | `VITE_API_URL` | `https://your-api-id.execute-api.us-east-1.amazonaws.com/Prod` |
   | `VITE_WS_URL` | `wss://your-websocket-id.execute-api.us-east-1.amazonaws.com/Prod` |

4. Select all environments (Production, Preview, Development)
5. Click **Save**

### For Local Development

Create a `.env` file in the `frontend/` directory:

```env
VITE_API_URL=https://your-api-id.execute-api.us-east-1.amazonaws.com/Prod
VITE_WS_URL=wss://your-websocket-id.execute-api.us-east-1.amazonaws.com/Prod
```

**Important**: Vite requires environment variables to be prefixed with `VITE_` to be exposed to the frontend code.

## Verification

After setting these values, you can verify they work:

### Test REST API
```bash
curl https://your-api-id.execute-api.us-east-1.amazonaws.com/Prod/health
# Should return: {"status": "healthy"}
```

### Test WebSocket
You can test WebSocket connection in your browser console:
```javascript
const ws = new WebSocket('wss://your-websocket-id.execute-api.us-east-1.amazonaws.com/Prod');
ws.onopen = () => console.log('Connected!');
ws.onerror = (error) => console.log('Error:', error);
```

## Troubleshooting

### Issue: "API endpoint not found"
- **Solution**: Make sure you've deployed the AWS backend first
- Verify the stack exists in CloudFormation console
- Check that the stack deployment completed successfully

### Issue: "WebSocket connection failed"
- **Solution**: Ensure you're using `wss://` (secure WebSocket), not `ws://`
- Verify the WebSocket API is deployed in AWS
- Check CORS settings on your API Gateway

### Issue: "Environment variables not working in Vercel"
- **Solution**: 
  - Make sure you added the variables to **all environments** (Production, Preview, Development)
  - Redeploy after adding environment variables
  - Verify variable names are exactly `VITE_API_URL` and `VITE_WS_URL` (case-sensitive)

---

**Quick Reference**:
- These values are **generated automatically** during AWS deployment
- They're displayed at the end of `./scripts/deploy.sh` or `./scripts/deploy.ps1`
- They're also available in AWS CloudFormation console under the "Outputs" tab
- Use them in Vercel environment variables for production deployment
